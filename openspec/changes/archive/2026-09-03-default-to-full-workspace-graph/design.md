## Context

See `proposal.md` for motivation. The verified constraint is that a privately published GitHub Pages site behind SSO returns a cold visitor to the pathname only: the query string is dropped by GitHub's `path`-only round trip and the fragment is lost because the flow passes through a real login page rather than a pure redirect chain. The same holds for GitLab's access-controlled Pages and for any proxy that interposes a login document. The site is static, so nothing can run before the proxy answers, and GitHub Pages offers no rewrite layer. The pathname is the only part of a link a publisher can rely on.

Today every context-bearing destination is query-carried: `/graph?brains=a,b` for combined views, `?focus=<compositeId>` for pinned neighborhoods, and `?brains=...&focus=...` threaded through note, search, tag, recent, and orphan links by `withBrainScope` and `withGraphContext` in `routes.ts`. `graph.astro` renders a recovery card when `brains` is absent, and `WorkspaceRouteRedirect.astro` sends root `/tags`, `/recent`, and `/orphans` to the chooser. `graph-view.ts` derives graph context from `activeBrainId` or the `brains` query, keeps a per-pathname `sessionStorage` flag for related-brain visibility, and already renders a dim-versus-emphasis split for hover and focus. `graph-data.json` contains every Brain's nodes and precomputed positions; contexts are derived client-side from it. Node identity is `compositeNoteId = <brainId>/<slug>`.

## Goals / Non-Goals

**Goals:**

- Make every shareable destination a pathname under the configured base, and make losing any query string or fragment degrade to a wider view, never to a selection step or recovery card.
- Add one generated neighborhood page per note that reuses the existing global graph runtime rather than a second graph implementation.
- Replace Brain selection with a personal lens whose precedence rules are explicit: focus beats lens, lens dims but never removes, filters remove.
- Delete the `?brains=` grammar and every code path that exists only to carry it, instead of leaving it dormant.

**Non-Goals:**

- Making the lens shareable, mirrored into URLs, or synced between devices.
- Pre-generating combined-subset graph pages or routing through `404.html` to reconstruct query state.
- Changing note slugs, canonical note paths, Markdown links, the build-time layout, or the local connection map on note pages.
- Adding a generator flag for proxy behavior; the path-only contract holds on every host, so there is nothing to configure.

## Decisions

### Identity lives in the pathname; the note owns its neighborhood

A focused neighborhood is identified by `<note path>/graph/`: `/brains/<id>/notes/<slug>/graph/` in workspace mode and `/notes/<slug>/graph/` in vault mode. One page per note is generated by a new dynamic route beside the note route in both modes, so the count equals the note count and no combinatorial output appears. `graph` is a fixed child segment of the note directory, so it cannot collide with a note slug.

Alternatives rejected: a fragment fallback (dropped by the login hop, verified on the user's site); a `404.html` path router (unbounded but returns HTTP 404, breaks unfurling, and depends on undocumented fallback behavior); pre-generated pages per Brain subset (2^N output and still no focus in the path); a `--link-context` generator flag (nothing to configure once every shareable link is a path).

### The neighborhood page is the global graph with a fixed initial focus

The new page renders `GlobalGraph` in the note's context (full workspace or vault) with data attributes for the focused composite ID. `mountGlobalGraph` reads that attribute in place of the `focus` query on this page and refuses to clear the initial focus on lens changes. The page's URL never gains a query string; pinning a different node on a neighborhood page navigates to that node's neighborhood page instead of rewriting the query. Graph pages that are not note-owned (`/` and `/brains/<id>/`) keep `?focus=` as in-session state written by `history.replaceState`, because losing it there degrades to the same page unfocused.

Reusing the global graph over a separate focused-graph implementation keeps hover, drag, filters, fit, legend, search, and label logic identical and keeps the 2,000-note budget in one place.

### Default is everything; the lens dims, filters remove, focus wins

The workspace root renders the `all` graph context that `buildGraph` already supports. The Brain control becomes a checkbox list of every configured Brain in declared hierarchy order, all checked, with an Enter action per Brain and a reset action. Unchecking a Brain adds it to the lens.

Lens state is a set of dimmed Brain IDs stored in `localStorage` under one key per site base, replacing the per-pathname `sessionStorage` related-brains key for the full graph. It is read at mount, applied through the existing node and edge reducers as a lower-emphasis treatment (the same visual grammar as unrelated nodes during inspection), and never written to any URL. Precedence in the reducers is fixed: focused neighborhood at full emphasis, then lens dimming, then normal styling; type, status, and tag filters continue to remove nodes before any of that applies. A lens that would dim every Brain is treated as empty at render time and the control reflects that.

`localStorage` over URL state because the lens is a personal habit, not a destination, and carrying it in links is exactly the failure being removed. `localStorage` over `sessionStorage` because the user expects the lens to survive between visits. If storage is unavailable the lens is held in memory for the page only.

### Connected domains are derived at render time

On a workspace-mode neighborhood page the focused node's direct neighbors are grouped by `brainId` from the loaded graph data. The list renders one chip per Brain with mark, accent, title, count, and a dimmed-elsewhere state, and each chip toggles that Brain in the lens. This is computed client-side from `graph-data.json` rather than emitted at build time so the chips stay consistent with the graph the reader sees and the page HTML stays a thin shell.

### Return context is in-session and degrades to the note's own page

Opening a note from a focused graph appends `?focus=<compositeId>` to the note URL, as today, but nothing else. The note page's Graph action resolves that value against the graph data: valid, and it links to that note's neighborhood page; absent or invalid, and it links to the opened note's own neighborhood page. Both are pathname-only links, so a proxy stripping the query changes which neighborhood opens, never whether one opens.

### Remove the selection grammar rather than deprecate it

`withBrainScope`, `withGraphContext`, `combinedRoutes`, `brainSelectionContext`, `canonicalBrainSelection`, the `brains` branches of `singularQueryValue` callers, `graph.astro`, `WorkspaceRouteRedirect.astro`, the combined branch of `GlobalGraph.astro`, the `brains-query` source in `not-found.ts`, and the quick switcher's retained-scope handling are deleted. `/graph` is kept only as a static redirect to the root so old links land on the full graph. Root `/tags`, `/recent`, and `/orphans` render the workspace aggregate using the existing per-Brain report components fed with the whole snapshot and an owner label per entry.

Deleting instead of leaving the grammar dormant avoids two link formats with different proxy behavior and removes the code that produced the recovery card in the first place.

### Home is the full workspace graph; the chooser's information moves, not disappears

`BrainChooser.astro` is retired as the root page. Hierarchy, descriptions, accents, and Enter actions are presented in the Brain control's expanded panel, and the About disclosure moves onto the root graph page. The root graph page is the only page that still exposes About.

## Risks / Trade-offs

- [Full workspace graph as the default load on large workspaces] -> The `all` context already exists and the `> 500` node label thresholds apply; run the stress suite against the demo workspace and a synthetic 2,000-note workspace before merge and keep the budget in the spec.
- [Previously shared `/graph?brains=` and `?brains=` note links change meaning] -> `/graph` redirects to the root, `?brains=` is ignored, and note links still open their note. Documented in the proposal as breaking; no data migration.
- [Dimmed can be mistaken for hidden] -> Legend and Brain control describe dimming explicitly, dimmed nodes keep hover and click, and domain chips on neighborhood pages state "dimmed elsewhere".
- [Stale lens surprises a reader who forgot it] -> The Brain control shows unchecked Brains at a glance and offers reset; focus always outranks the lens so shared destinations look right regardless.
- [Neighborhood page doubles the note-derived page count] -> Each page is a shell; measure build time on the demo workspace and the stress fixture and confirm the increase is proportional to note count only.
- [Playwright cannot emulate the SSO proxy] -> Cold-link tests open pathname-only URLs in a fresh browser context, and a route-level test asserts that no generated shareable link contains `?` or `#`.
- [Losing the exact-subset shareable view] -> Accepted; the full graph plus the lens covers narrowing, and the neighborhood page covers sharing. Revisit with pre-generated subset pages only if a concrete need appears.

## Migration Plan

1. Add the neighborhood route, page, and mount-time focus attribute; switch copy-link and note Graph actions to the path form. Existing query links still work at this point.
2. Introduce the lens, the checkbox Brain control, and the root full graph; make `/graph` redirect to the root.
3. Remove the `?brains=` grammar, combined-view code, the chooser page, and the root report redirects; render workspace-wide reports.
4. Update unit, browser, and stress tests; capture before and after screenshots; update README URL examples.

Rollback is a revert of the branch. Neighborhood pages are additive and harmless if the rest is reverted; the lens key in `localStorage` is ignored by the previous code.
