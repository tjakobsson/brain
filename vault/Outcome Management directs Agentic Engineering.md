> "Outcome Management: A systems-level leadership practice that aligns strategy, design, delivery, decision-making, and measurement to business and customer outcomes."
>
> Mik Kersten, *Output to Outcome*

## Two connected ideas

Kersten uses **Agentic Engineering** for software development in which coding agents take on substantial execution. Agents can produce code, tests, designs, experiments, and features at a speed and scale that were previously impossible.

He uses **Outcome Management** for the operating model that directs this capacity. It connects strategy, investment, delivery, and measurement to changes that matter to customers and the business.

The distinction matters because cheap output does not guarantee value. Agentic Engineering can accelerate useful work, but it can also produce more features nobody needs. Once making things is no longer the main constraint, choosing what matters and learning whether it worked become the constraint.

## The division of responsibility

- **Agents amplify outputs.** They explore options and execute work.
- **Humans own outcomes.** They define the intended measurable change, remain accountable for it, and decide whether to continue, change, or stop.

Outcome Management is therefore the control system for Agentic Engineering. It keeps agent activity tied to human intent instead of treating code volume, token use, or feature count as proof of value.

## The Outcome Loop in development

1. Define a measurable customer or business outcome.
2. State an outcome hypothesis: *If we build X for Y, we expect metric Z to change.*
3. Let agents produce the smallest useful experiment or output.
4. Measure whether the expected effect occurred.
5. Continue, change, or stop based on the evidence.

The goal is not maximum agent activity. It is the shortest reliable loop from human intent, through agent-produced output, to a measured effect.
